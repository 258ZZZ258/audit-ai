# 按事项分组与漏项检查

现有规则继续由请求提供，按材料类型给出字段。抽取模型区分 FINDING / RECTIFICATION / ACCOUNTABILITY / LITIGATION；本次不修改业务类别字典或让模型改写上传类别。

`config/supervision.toml` 已启用 `coverage_review=true`。底层 prepare_extraction 和不包含该字段的外部配置默认关闭额外模型检查，调用者需要明确启用；已启用时失败不得退回单轮成功结果。

## 分组

优先识别显式“问题一”“第一章”“一、”等事项边界和独立表格行，先组成事项单元，再在容量内打包多个单元；容量不够优先在单元之间分开。单元过长才按证据边界拆分。所有原文证据都参与抽取，表格行保留表头。单个页面窗口或表格行超限仍报错，绝不截断。PDF 页面内部未独立解析出的事项不保证能识别其结构边界。

## 独立漏项检查

每组首次抽取后，把同组全部证据、原候选、规则再次提交检查。要求 checkedEvidenceIds 唯一完整覆盖输入；允许 additions 补漏掉的独立事项，supplements 指定原候选索引和已有逐字引用锚点补字段。新字段继续通过原规则、单位范围、逐字引用和派生定位验证，随后仍由 Pi 做字段语义核验，候选不会直接升级为已确认事实。

已有日期、金额、状态等字段不可覆盖。描述类字段允许追加细节，但必须完整保留原描述文本和所有原引用，并附新增证据；不能以改写形式删除原事实。模型未返回完整检查结果、无效目标/锚点、伪造引用时整次失败。成功记录 COVERAGE_REVIEWED 的证据集合与补充数量。调用或结构解析失败有限重试，证据校验不放宽。

## 相邻组补全

对相邻组末条/首条证据再次检查。只处理全部原引用都落在这个窗口内的候选，仅补字段，不添加、删除或合并候选。没有明确同一事项依据不补；跨资料问题与整改关联继续沿用后续关联流程。

两条证据总长度超限记录 BOUNDARY_REVIEW_SKIPPED_CAPACITY；没有能完整回溯的候选记录 BOUNDARY_REVIEW_NO_COMPLETE_TARGET。成功记录 BOUNDARY_REVIEWED。这些记录不是“无遗漏”证明；非相邻跨组信息、超长单页、缺少明确编号的重复问题仍需扩展材料评测，不能凭相似性自动合并。

覆盖检查增加一次组级模型调用及可选边界调用，复用现有缓存；缓存键加入覆盖提示词和开关，旧单轮结果不会在新配置下命中。

## 验证

`pytest pipeline/tests/test_supervision_coverage.py` 覆盖结构分组、漏记录恢复、字段补全、描述扩展、跨组补充、非法覆盖/目标/锚点、遗漏证据清单、伪造引用。

真实模型使用最小模拟 IR（1条问题正文、2行不同单位整改数据）运行全文抽取和覆盖检查，得到1条FINDING与2条RECTIFICATION。该验证不是客户PDF/OCR准确率或Java全链路验收。
