# 监督调用优化与评测

## 缓存边界

监督抽取使用有界进程内缓存。键包含完整请求（规则、单位及业务元数据）、IR、索引指纹、模型实例/名称、配置和提取提示词。命中前后仍读取 PG/IR/索引，停用、替代、降级或内容变化不会因缓存而放行。缓存返回独立副本；失败不缓存。同键并发共享计算，不同键可以并行。

字段核验与关联判定只缓存经过原有完整校验的结果。键包含完整输入、操作、提示词、模型名称、网关和凭据指纹、配置。否定和不确定结果同样保留。仅 LLMError 按 model_attempts 有限重试；证据不匹配、非法 verdict、ID 不完整不重试放宽。测试注入客户端走直接验证路径，缓存路由另有专用测试。

向量缓存绑定同一个嵌入客户端实例，按全文哈希复用；跨 pair 批次只计算此前没有的文本。完整批次校验通过才缓存，维度变化清空并报错。只缓存纯文本向量，不缓存业务授权或问题确认。替换同名模型的部署权重或更换模型配置后须重启服务。

`supervision.toml` 配置 cache_entries=32、embedding_cache_entries=4096、cache_ttl_seconds=900；entries=0 可关闭对应结果缓存。缓存不落数据库和磁盘、不跨进程共享，重启后重新计算。关联仍在已经限定的资料范围内逐对评分，阈值和跨问题歧义保护不变；这次没有引入可能漏掉冲突候选的 TopK 裁剪。

## 可执行最小模型评测

设置现有模型环境变量后执行：

```sh
python -m pipeline.supervision.evaluate --output evaluation.json
```

使用真实配置网关，输出模型名称、逐案例期望/实际、通过数；任一错误或失败非零退出，拒绝覆盖既有文件。固定8种材料场景的字段证据检查及3种关联场景，共11项，含金额、主体、否定、部分完成、缺资料、同事项、不同事项、泛化整改。数据是最小模拟文本，不包含客户文件；此分数不等于真实PDF解析/全量抽取准确率。
