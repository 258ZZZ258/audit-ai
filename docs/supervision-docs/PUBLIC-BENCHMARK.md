# 公开材料抽取诊断评测

入口：`python -m pipeline.supervision.public_benchmark --dataset <dataset.json> --output <new-results.json>`。
模型凭据通过运行环境加载，结果必须写入新文件。原件、标注及模型完整输入输出保存在外部评测目录，不随代码提交。

## 范围与计数

首批使用官方公开监管文书、审计整改对照表、问责案例及证券公司半年报的完整页面或完整案例范围。
它是诊断集，不是随机抽样的生产验收集。标注由 AI 对照原文制作，尚未经过独立人工复核。
公开部门审计和问责不能冒充证券公司内部审计/问责材料，半年报不能当作连续月份诉讼月报。

- 监管文书按明确列示的上位事项计数，同时要求描述保留下位具体行为。
- 整改表按原表完整行计数；复述的历史问题不另算新发现。
- 问责按可识别的个人或受罚机构计数；相同匿名姓名但不同职务不自动合并。
- 诉讼按独立案件计数；历史公告引用日期不分别生成新案件；相同对手方的不同债券保持独立。
- 未明确身份/处分的“其他相关人员”不补造记录。

## 输入和复现

数据集包含 `id`、`scope`、`cases`。每个 case 包含：

- `id`、`sourceGroup`、`split`、`sourceUrl`、`originalSha256`；
- `inputFile`（相对数据集目录）、`inputSha256`、`format`，PDF 可指定原始 `pages`；
- `request`：真实 `SupervisionExtractRequest` 契约；只含机构目录、字段规则、资料元信息；
- `gold`：`id`、`type`、`orgs`、`identity`、`fields`、`sourceLocator`。

PDF 保留选定原页内容和布局，交由生产 `LightParser` 解析，再恢复原页码。此结果仅代表指定范围，不是整份报告召回率。HTML 正文按原段落转 DOCX，再走 DOCX 解析；须明确标识这种转换，不称为原生 Word 或 PDF。

每个 gold 字段 rubric 使用 `equals`（允许值列表）或 `allOf`（每组满足一个同义表达）和可选 `noneOf`。每个 case 不超过 16 个 gold；一对一匹配使用有限状态搜索，避免重复输出提高召回率。
未标注的请求字段按不应填写处理，因此必须预先复核可选字段是否允许填值；合理但未列入允许集的表达可能是假阴性，需要在原始成绩之外单列复核，不覆盖原始结果。

## 指标含义

1. `facts`：类型、机构集合、输出中的身份特征及其逐字引用均满足标注后，一对一匹配的精确率/召回率。不是全文语义真实性指标。
2. `fieldRubric`：关键事实词组或规范值的覆盖精确率/召回率。错误字段同时计 FP 和 FN；额外字段计 FP；不能简称“字段语义准确率”。
3. `citationIntegrity`：引文是否为对应证据的原文子串。逐字引用合法不等于引文支持全部结论，语义支持仍需复核。
4. `failedCases`：解析或抽取失败逐项列出。正例失败保留全部 FN；负例失败不能当作正确拒绝。

不将整页正文代替模型实际引文进行匹配。保存每次模型输入/结构化输出、IR、原始预测、失败阶段、耗时、逐字段明细、数据集及提示词校验值。结果可能包含公开文书个人信息，不应默认上传共享仓库。

同一来源组不能跨不同 split；同份报告正文/附件、同一事件的公司与个人决定及后续公告，建集时须用同一个来源组。标注、规则或提示词已参考过的结果不得作为未见留出测试结果。生产抽取提示词不因运行此脚本而修改。
