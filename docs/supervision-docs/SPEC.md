# 监督上传元数据与正文提取

Java 负责上传、业务元数据和权限。audit-ai 接收本平台文档/版本及标题、发文日期、类别、涉及单位，复用 S0–S5 已产生的 IR 和索引内容，输出带原文位置的业务字段候选。无需甲方原始记录、导入记录或新上传流程。

新增内部 `POST /v1/supervision/extract`，沿用 X-Internal-Token 服务鉴权，不识别用户身份。调用方 Java 必须先授权所选版本。只接受已 INDEXED 且 effective 的版本，文档与版本不匹配、缺 IR 或索引未就绪均不生成成功结果。不重新 OCR，不调整既有 S4 审核、manifest、PG/Milvus schema。

基础元数据以 Java 输入为准，正文发现只作校验候选，不静默覆盖。日期候选不自动当作发文日期；上传部门和上传时间不能推定业务单位或期间。单位目录随请求提供已授权资料涉及的单位，用于将正文单位名对应到 ID。

输出分为 uploadedMaterial（可接 Pi 上传适配）、evidence（完整 IR 段落/表格逐行及版本、定位）、facts（按规则提取的字段候选）和 metadataChecks。逐字段必须引用本次原文证据并提供可逐字核验的摘录；不认识的规则、字段、单位、证据或不存在的摘录拒绝。候选不等于确认事实，不自动转换为已确认问题或整改关系。

提取模型默认关闭，关闭时返回 EVIDENCE_READY + 空 facts，明确没有执行语义提取；开启后复用现有 LLMClient，逐组处理全部证据，不以 TopK 丢弃统计范围。单段超过配置容量显式报错，不截断。模型失败不伪装为没有问题。

文本型 PDF 的 LightParser 产物通常按排版行分块。监督提取层将同一页连续、无布局坐标和 OCR 置信度的普通文本块组成 PAGE_TEXT 引用窗口，原换行不变，保留起止 block 编号；不跨页、表格、标题或 OCR 布局块，不改存储 IR。窗口超过单次容量仍显式报错。模型不得缩写证据 ID 或重新拼接 quote。

规则中的 evidenceLocation 是派生定位字段，不交给模型抽取；后端依据每个已校验业务字段所引用的证据页码和块范围生成。该字段的 value 来源于证据元数据，附带首个业务字段的 evidenceId/quote 作为可回溯入口；其余业务字段仍保留各自完整引用。missingRequiredFields 在派生定位后计算。

## 跨页事实补全

字段保留原有 value/evidenceId/quote，并新增可选 supportingEvidence（若干 evidenceId/quote）。主引用与补充引用共同支持同一字段的完整事实；每条摘录仍必须是其对应原文的连续子串，逐条校验当前证据组、完整 ID 与原文，不允许拼接摘录或引用未提供的另一组内容。旧单引用输出继续有效，空补充列表不输出，保持旧候选结构及 ID 稳定。

模型长摘录可能重新折行。仅对 PAGE_TEXT，若原摘录未直接命中，可忽略 CR/LF 尝试唯一连续匹配；其他字符、空格、数字、标点必须完全一致。唯一命中后回填原文原始连续子串，并记录 metadataChecks.code=PDF_QUOTE_LINE_BREAKS_RESTORED。未命中或多处命中拒绝；不做模糊匹配、字符纠错或删词，不改 value/IR。PARAGRAPH/TABLE_ROW 不应用此校正。返回引用依然可直接在原文中逐字找到。

同一文档明确关联的具体经过与责任结论可以合并为一个跨页事实字段，分别引用各页。问题描述须保留与违规判断有关的主体、行为、先后时间、金额/比例、披露缺失及责任认定；不能仅输出笼统结论。不同单位、无明确关联的事项或表格行不得因此混合，不能将“分多页”自动当作“多个问题”。后端派生定位收集主引用和所有补充引用，消费方也须保存完整引用集合。

验收：旧单引用兼容、多页字段与全部页码保留、补充引用伪造/错版本/非逐字/跨组引用拒绝；使用相同上交所原始 PDF、相同规则和模型实测，人工核对第 2 页具体经过与第 3 页责任结论进入同一问题描述且引用覆盖两页。超出单组容量时仍全量分组提取，不在本次修改中默默跨组拼事实或改变问题计数规则。
